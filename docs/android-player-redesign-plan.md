# 安卓端播放器整体改造计划

状态：已完成安卓端改造与模拟器验收（2026-10-12）。

## 目标与范围

- 面向安卓端真实触摸操作，重新梳理播放器在各页面、弹层和不同播放状态下的布局与交互。
- 解决播放条遮挡内容、折叠后仍占空间、控制重复或难以触达、页面切换时状态不连续等问题。
- 安卓页面按可用视口自适应，不把 16:9 当成固定画布，不裁掉内容来迁就比例。
- 本计划中的 UI 改动只针对安卓端；Windows 桌面端行为和布局保持不变。
- 不以“遇到页面就隐藏播放条”作为通用遮挡方案。优先使用紧凑停靠、折叠、展开避让和安全区布局；确有模态交互时，明确音乐继续播放和恢复行为。

## 用户流程与界面策略

| 界面 / 场景 | 用户正在做什么 | 播放器应该如何表现 |
| --- | --- | --- |
| 首页：歌单、电台、专辑 | 浏览内容、选择歌曲、切换分类 | 播放条默认紧凑停靠在不遮挡主要内容的位置；歌名可读，播放 / 暂停可直接操作；展开后可收回。不能挡住封面、标题、搜索和主要按钮。 |
| 首页：搜索与在线平台连接 | 搜索歌曲，选择音源或连接账号 | 播放控制保持可用但不盖住搜索结果、平台入口或连接按钮；内容区域需为停靠控件留空间或让播放器进入更紧凑态。扫码时二维码、状态提示和关闭按钮完整可见。 |
| 完整播放器 | 查看当前歌曲并控制播放 | 主播放控件、上一首 / 下一首、循环、进度和歌词入口职责清晰；重复功能不同时堆在迷你条和主界面造成混乱。返回后维持歌曲、队列和播放进度。 |
| 队列列表 | 查看接下来播放的歌曲、调整顺序、移除或跳播 | 迷你播放条不遮挡队列首尾和行内操作；队列操作即时反馈，当前播放项清晰；从队列打开完整播放器后可返回原滚动位置。 |
| 队列拼贴 / Lattice | 浏览歌曲拼贴、聚焦当前歌曲 | 播放条不压住中心歌曲卡、歌词、焦点按钮或右侧控制；当前歌曲切换与拼贴聚焦保持同步，避免播放条和拼贴内播放器重复争抢视觉焦点。 |
| 歌词与歌词 MV | 跟随歌词播放、切换 Folia / Jizura、调整 MV | 歌词可读区域优先；必要控制按需展开或收起，不覆盖歌词行。Folia 和 Jizura 控件保持各自职责，切换动画不打断音频播放。 |
| 扫码登录、账号切换、设置弹层 | 扫码、选择平台、调整设置 | 弹层内容和关闭入口优先可操作；播放不中断。播放条使用适合短屏的紧凑态或布局避让，关闭后恢复进入弹层前的播放器状态，不无故消失或留在错误位置。 |

## 播放器状态与交互规则

1. **折叠态**
   - 安卓首页默认使用小尺寸迷你条，优先停靠在不挡核心内容的边缘区域。
   - 保留播放 / 暂停、简短曲名、细进度提示和明确的展开入口；长曲名截断，不挤压操作按钮。
   - 进度可拖动时保证有效触摸面积；视觉轨道可以细，但触控命中区不能随之变得难点。

2. **展开态**
   - 用户主动展开后显示较完整控制，并提供明显的收起按钮。
   - 展开 / 收起有稳定、克制的过渡；不能引发周边卡片横向缩动、闪动或页面跳位。
   - 点击播放键、进度、队列等子控件只执行该控件动作，不应误触发跳转或折叠。

3. **播放生命周期**
   - 覆盖无歌曲、准备中、播放中、暂停、切歌、时长未知、播放错误、音源失效等状态。
   - 切歌时曲名、封面、时长、进度和歌词对应同一首歌，避免旧状态残留或短暂空白。
   - 页面切换、弹层开关、旋转 / 尺寸变化不能重置当前播放状态、队列或有效进度。

4. **返回与触摸反馈**
   - 系统返回优先关闭最上层弹层，其次返回上一个播放器页面；不意外暂停音乐或清空队列。
   - 所有关键按钮均有清楚状态、足够触摸面积和无障碍名称；禁用状态应可辨识。

## 实施阶段

### 阶段一：现状审计与基线记录

- 梳理 `FloatingPlayerControls`、完整播放器、队列、Lattice / 歌词 MV、账号弹层和播放状态的组件与数据来源。
- 在安卓模拟器记录首页、完整播放器、队列、拼贴、歌词、登录弹层等基线截图和操作路径。
- 标出重复控件、遮挡区、页面滚动归属、定位 / 安全区和触摸命中问题。
- 先确认现有数据与状态责任，避免视觉调整破坏播放逻辑。

### 阶段二：明确播放器层级与布局规则

- 确定迷你播放条、完整播放器、页面内播放控件的唯一职责。
- 明确各场景播放器的停靠位置、折叠条件、展开行为、弹层避让和返回恢复规则。
- 以安卓实际可用视口自适应布局；分别考虑矮横屏、宽横屏和不同窗口尺寸。
- 先处理布局与交互，不用遮罩、裁剪或永久隐藏来掩盖内容冲突。

### 阶段三：分界面实现

1. 迷你播放条：折叠尺寸、停靠位置、播放 / 暂停、进度触控、展开 / 收起。
2. 完整播放器：主要控制层级、切歌与进度交互、返回行为。
3. 队列与拼贴：播放条避让、队列操作触达、当前歌曲同步。
4. 歌词与 MV：可读区域、控制入口和 Folia / Jizura 的独立交互。
5. 搜索、账号连接、扫码和设置弹层：短屏布局、操作优先级与关闭恢复。

每完成一个界面，都先在模拟器实际操作并根据截图修正，再进入下一项。

### 阶段四：真实交互验收与回归

- 在模拟器实际点击、拖动、滑动、系统返回和切换页面；不以“编译通过”代替 UI 验收。
- 对比每个场景的修改前后截图，确认没有内容被遮挡、裁切或挤压。
- 检查不同横屏宽高、系统状态栏 / 导航栏安全区及窗口尺寸变化。
- 检查进度更新、动画、切歌和队列操作没有明显卡顿、闪动或异常 CPU 占用。
- 对照验收清单逐项记录通过 / 未通过；未通过项继续修正，不提前宣告完成。

## 验收标准

- 首页、队列、拼贴和歌词的核心内容及主要操作不被播放器覆盖。
- 折叠态明显比完整播放器紧凑；展开和收起入口明确且都能实际操作。
- 扩展控制不会误触播放、跳转或队列操作；返回后音乐、进度和页面上下文保持合理。
- 扫码登录和设置弹层中的内容、按钮及关闭入口可完整看到并触摸。
- 歌曲切换、暂停 / 恢复、时长未知和播放失败等状态显示正确，不出现旧曲信息残留。
- 不依赖固定 16:9 画布，不以裁剪、压缩内容或普遍隐藏播放条达成“不遮挡”。
- 安卓模拟器逐场景实测通过；桌面端无回归。

## 实施与验证记录

- 安卓首页播放控件改为边缘停靠的紧凑条，展开态使用专门的双行紧凑控制，提供清晰的播放 / 暂停、进度和收起入口；不改变桌面端的既有展示。
- 横屏小视口打开输入法时暂时让出可视区域，键盘关闭后自动恢复播放条；无有效时长的音源显示 `--:--` 并禁用无效拖动。
- 队列拼贴界面由拼贴内的播放控制负责，避免全局播放条重复覆盖；命令面板队列底部操作、可视化预览和设置工作台按安卓短横屏做了自适应排布。
- 安卓系统返回复用页面现有 Escape 关闭顺序：先关弹层 / 菜单，再返回播放器子页或拼贴；根页面将 Activity 最小化，避免退出时丢失内存中的播放队列。在线平台登录弹层可通过返回键关闭。
- 在 640×360 与 480×320 两种模拟器视口验证首页、搜索键盘、设置及歌词预览、账号弹层、完整播放器、队列入口、拼贴聚焦和返回路径；从根页面最小化并重新打开后，当前曲目与首页上下文保留。
- CPU 抽样中播放器进程约 0–1%、WebView 渲染进程约 1%；这是当前模拟数据的短时观察，不代表所有歌词 MV / 长队列负载。最近日志未见 fatal 或未捕获 JS 错误。
- 定向单元测试：导航、拼贴布局 / 歌词、可视化注册和设置导入导出共 6 个文件、71 项测试通过；`git diff --check` 通过；Capacitor Android debug APK 构建成功。
- 模拟器音源/API 未完整配置，登录二维码与真实在线播放、真实歌词时序无法端到端确认；UI 登录路径和无时长状态已检查。仓库未安装/配置 ESLint，因此未把临时 ESLint 调用结果作为验收项。
